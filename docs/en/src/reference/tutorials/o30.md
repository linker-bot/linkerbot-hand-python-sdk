## Classic CAN Connection and Test

The hand and adapter must already use classic CAN at matching nominal bitrates. This complete read-only example uses a right hand, default request ID `0x001`, and 1 Mbit/s:

```python
from linkerbot_hand import DeviceConfig, HandDevice, TransportKind
from linkerbot_transport.can import CANTransport

hand = HandDevice(
    model="O30",
    side="right",
    transport=CANTransport("can0"),
    config=DeviceConfig(hop_transport=TransportKind.CAN, hop_request_id=0x001),
)
try:
    hand.open()
    print(hand.get_device_info(timeout=2.0))
    print(hand.get_angles(timeout=2.0).raw)
finally:
    hand.close()
```

`hop_transport` selects SDK framing; it does not reconfigure the device or adapter. Classic CAN requires BRS off. For CAN FD, keep the existing FD transport and omit `hop_transport` or select `TransportKind.CAN_FD`. The default left-hand request ID is `0x002`; use the actual ID for configured devices. The response ID is the request ID `| 0x400`. Firmware without side information remains `PARTIAL` during discovery and requires an explicit side for construction.

Run from the repository root using a Python environment with this SDK source installed:

```bash
# Read identity, 15 state/configuration objects, tactile data, poll, reopen, recover
python examples/o30_classic_can.py --channel can0 --side right

# Write existing settings back, verify configuration readback, move one joint,
# then restore the original target registers
python examples/o30_classic_can.py --channel can0 --side right --write-back --motion-joint 6 --delta 2

# Request 50 Hz angle polling and save measurements and raw frames
python examples/o30_classic_can.py --channel can0 --side right --angles-hz 50 --duration 5 --report o30_can_report.json
```

`--motion-joint` is a zero-based joint index; `--delta` is a nonzero raw angle change from -5 to 5. Motion commands are disabled by default. `--write-back` writes existing configuration values only; it sends no angle command. The motion exercise reads the actual target registers, preserves the other joints' targets, and restores and verifies the original targets on completion or error. The script does not change CAN ID, bitrate, mode, or flash settings, and does not switch back to FD. The default request ID follows `--side`; override it with `--request-id 0x123` when needed.

Classic CAN carries at most five object payload bytes per frame. The SDK splits long reads and 25-slot whole-hand writes into requests of at most five bytes, waiting for each reply before sending the next request. Read results update the complete state only after all ranges arrive. A failure stops subsequent stages; already applied writes cannot be rolled back. CAN FD retains its existing read behavior. Whole-hand writes and returned states are not simultaneous, and acknowledgement does not prove mechanical arrival. Polling rates are requested targets; the report counts observed new samples. `snapshot` holds the latest complete state, rather than a queue.

`--motion-timeout 2` queries current angles for about two seconds after writing the test targets and again after restoring the original targets. The script strictly verifies target registers and records actual angles, deviations, and changes in other joints. Physical behavior may produce a target offset or no observable movement; these observations do not fail SDK validation. `PASS` means communication and target readback passed, without guaranteeing mechanical arrival or accuracy. `--delta` is relative to the original target and does not bound actual displacement. Protocol, communication, or target-readback errors produce `FAIL` and exit code 1. Do not run another query or command producer on the same endpoint during this script.

`NO_SENSOR` is reported as `SKIP`; zero values remain unchanged and do not imply a fault. Some firmware reports the previous interface type after switching, so verify the actual CAN frame flags too. Mode changes that are not saved to flash may revert after a power cycle.

O30 and P7 have been tested sharing a classic CAN bus, with both SDKs in one process and device close/reconnect exercises. Joint polling at 50 Hz still showed occasional query timeouts and stale data. Automatic retries have not been added, and the cause remains undetermined. This establishes basic communication compatibility, without guaranteeing continuous 50 Hz updates without loss.

The remaining examples use an already connected `hand`; call `hand.close()` when finished.

## Joint Order

The SDK reads and sets joint data in the following order.

| Position | `joint_names` | Joint |
| ---: | --- | --- |
| 1 | `thumb_rotation` | Thumb rotation |
| 2 | `thumb_roll` | Thumb roll |
| 3 | `index_abd` | Index finger abduction |
| 4 | `middle_abd` | Middle finger abduction |
| 5 | `ring_abd` | Ring finger abduction |
| 6 | `pinky_abd` | Little finger abduction |
| 7 | `thumb_root1` | First thumb root joint |
| 8 | `index_root1` | First index finger root joint |
| 9 | `middle_root1` | First middle finger root joint |
| 10 | `ring_root1` | First ring finger root joint |
| 11 | `pinky_root1` | First little finger root joint |
| 12 | `index_root2` | Second index finger root joint |
| 13 | `middle_root2` | Second middle finger root joint |
| 14 | `ring_root2` | Second ring finger root joint |
| 15 | `pinky_root2` | Second little finger root joint |
| 16 | `thumb_tip` | Thumb tip |
| 17 | `index_tip` | Index finger tip |
| 18 | `middle_tip` | Middle finger tip |
| 19 | `ring_tip` | Ring finger tip |
| 20 | `pinky_tip` | Little finger tip |

<a id="angle-control"></a>

## Angle Control

### Reading Angles

`get_angles()` reads the current angles once and returns the following fields:

- `raw`: raw angle values returned by the device, ranging from 0 to 255. Larger values mean more flexion; smaller values mean more extension.
- `percent`: converted angle percentages, ranging from 0 to 100. Smaller values are closer to closed; larger values are closer to open.


```python
sample = hand.get_angles(timeout=1.0)  # 读取一次，最多等待 1 秒
print(sample.raw)  # 原始角度值
print(sample.percent)  # 角度百分比
```

### Setting Raw Angles

`set_angles()` accepts 20 raw angle values in `joint_names` order.

```python
# 按 joint_names 顺序设置角度
print(hand.set_angles([128] * 20).wait(timeout=1.0))
# 回读当前角度，核对真机姿态
print(hand.get_angles(timeout=1.0).raw)
```

### Setting Percentage Angles

`set_percent_angles()` accepts 20 angle percentages from 0 to 100. For flexion joints, 0 is the flexed endpoint and 100 is the extended endpoint.

```python
# 按 joint_names 顺序设置百分比角度
print(hand.set_percent_angles([50] * 20).wait(timeout=1.0))
```

### Reading Tactile Data

O30 tactile fields and the number of values per finger depend on the actual sensors; they are not fixed two-dimensional arrays.

| Field | Meaning |
| --- | --- |
| `fn` | Normal tactile data |
| `fns` | Per-finger normal summary |
| `ft` | Tangential tactile data |
| `fts` | Per-finger tangential summary |
| `fd` | Tangential direction data |
| `fds` | Per-finger tangential direction summary |
| `px` | Proximity sensor data |

`get_force()` requests `fn` and `fns` by default and also returns other fields provided by the sensors in the same sample. If the sensors do not provide these two fields, use a call such as `get_force("ft", timeout=1.0)` to request a supported field.

Each field's `raw` stores raw values per finger. `valid_values` marks whether each value is valid. A field or finger value of `None` means no data was provided. Direction and proximity data retain raw values from the device protocol.

```python
# 读取一次触觉数据，查看各字段
force = hand.get_force(timeout=1.0)
# Inspect this sample’s tactile fields
for name in ("fn", "fns", "ft", "fts", "fd", "fds", "px"):
    # Get the named field; unavailable fields return None
    field = force.field(name)
    if field is None:
        continue  # 跳过未提供的字段
    # Print the field name and raw values
    print(name, field.raw)
    print("有效值标记", field.valid_values)
```

### Reading Normal Resultant Forces for Five Fingers

`get_normal_force_resultant()` reads the normal summary `fns` for each of the five fingertips. If the device does not provide all five values, the SDK raises an error. It does not fill missing values with 0 or sum the tactile array.

```python
# O30 每指读取一个 FnS，缺失不补零
sample = hand.get_normal_force_resultant(timeout=1.0)
print(sample.sensor_names, sample.raw, sample.units)
```

### Reading Voltages

`get_voltages()` reads joint voltages. `raw` contains the raw voltage values from the device protocol.

```python
# 读取各关节电压原始值
```
