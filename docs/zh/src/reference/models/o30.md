# O30 接口与原始数据

统一字段入口见[全型号触觉接口](../force.md)。`get_force(timeout=1.0)` 默认 fn+fns，
单独选 `"fn"` 或 `"fns"` 都读取完整原生流并返回两者；ft/fts/fd/fds/px 按实际
descriptor 提供。字段频率取同一物理查询的最大值，每次查询只统计一次。

本文覆盖 HOP 0.0.4 的 SDK 公共接口。2026-09-17 已用固件 1.1.0、带五指 TSSP_JZG
传感器的左手核对常用读写与 CAN 回包；软件边界另由协议向量回归覆盖。
这是已验证版本的记录，不表示“1.1.0 以上必然支持全部功能”，也不是连接门槛。
SDK 不按版本拒绝旧手，不添加旧协议回退；具体可用性以实际响应和运行时 capability 为准。

## 连接和数据约定

- 标准 CAN FD，仲裁速率 1 Mbit/s，SDK 发帧不使用 BRS；当前发送路径不按接口 dbitrate 拒绝连接。
  接收侧固件是否始终不使用 BRS 未作全版本保证，总线配置仍需匹配实际设备。
- 默认右手请求/回复 `0x001/0x401`，左手 `0x002/0x402`。可配置端点见
  [自动发现说明](../hand-discovery.md)；改变 SDK 连接地址不等于写设备 ID。
- `set_angles()`、`set_speeds()` 及各 raw getter 直接使用协议整数，不做 LUT、角度或力单位换算。
  `set_percent_angles()` 接受 0..100 并做固定映射。
- `AngleSample.raw` 是公共通道投影，`percent` 是固定映射；当前没有可靠物理标定，
  `physical_rad` 的各通道为 None。触觉 `raw_data` 才是所选传感器的完整数据字节，仍不包含 CAN 头。
- `get_capabilities()` 不发帧；单位与置信度读取 `raw_unit/raw_scale_note/unit_confidence`。
  getter/polling 均保留 raw，消息时间与 sequence 描述 SDK 收齐样本的时刻，不证明物理同时采样。

## 控制、查询与单位

下表向量均为 20 个 `u8` 公共值、范围 0..255。RTS 选择回复视图：0 为当前状态，1 为
设定值；不是是否写入的开关。所有支持的写接口以完整相关回复确认 `ACKNOWLEDGED`，
不是机械到位。配置写入后需要新配置样本时调用相应 getter。

| 写接口 | 查询接口 | MI；查询 RTS | 原始单位和解释 |
| --- | --- | --- | --- |
| `set_angles()` / `set_percent_angles()` | `get_angles()` | 0x01；0 | count，归一化位置；角度写回复是否用于反馈读取 `returns_current_state` |
| `set_speeds()` | `get_speeds()` / `get_configured_speeds()` | 0x02；0 / 1 | count；实测速度与速度限制/目标速度分开，RPM 比例未知 |
| `set_accelerations()` | `get_configured_accelerations()` | 0x03；1 | count；加速度限制，物理比例未知 |
| `set_current_limits()` | `get_currents()` / `get_current_limits()` | 0x04；0 / 1 | count；当前电流与限制分开，不是 mA，写回复选择 RTS=1 |
| 无 | `get_voltages()` | 0x05；0 | count；物理电压比例未知 |
| `set_torques_limits()` | `get_torques()` / `get_torques_limits()` | 0x06；0 / 1 | 转矩字段原值；没有 N·m 比例，SDK 单位未知 |
| 无 | `get_temperatures()` | 0x07；0 | 当前能力保守标 count/UNKNOWN；本机 0x43 单位回复 degC，尚未校准跨固件比例 |
| `set_motion_times()` | `get_motion_times()` | 0x08；1 | count；现有 metadata 记载资料 10 ms/count，本机 0x43 回复 normalization，不能当作已验证换算 |
| `set_stall_detection_times()` | `get_stall_detection_times()` | 0x09；1 | 原始堵转判定时间；物理单位未知 |
| `set_stall_thresholds()` | `get_stall_thresholds()` | 0x0A；1 | 原始堵转阈值；单位未知 |
| `set_stall_hold_currents()` | `get_stall_hold_currents()` | 0x0B；1 | 堵转维持字段原值；电流比例与物理效果未核实 |
| 无 | `get_faults()` | 0x0C；0 | 位掩码；`raw` 与逐关节 `statuses` 同时保留 |

堵转保护的三个 getter 分别读取对应配置，不是设备原子读取三者。
电流 `0x04` 与转矩 `0x06` 独立：实时值分别在 `snapshot.currents/torques`，
限制值分别在 `snapshot.current_limits/torques_limits`，不会互相覆盖。
`PollingPlan(current_hz=..., torques_hz=...)` 分别调度两个实时通道；配置不加入高频轮询。
`set_torques()` 当前未声明；存在转矩读接口不能推出支持力控写接口。
O30 当前也未开放 `enable/disable/calibrate/clear_faults/save_parameters` 或限位补偿。

故障位按资料解码：bit0 手层堵转、bit1 执行器层堵转、bit2 过流、bit3 过温、
bit6 执行器异常、bit7 执行器离线，bit4/5 保留。未人为制造这些故障来验证物理含义。
HOP `0x4F` 通信错误与上述关节故障是两类数据，不应混用。

## 触觉与合力

`get_force(timeout=...)` 当前读取全部五指，暂不接受单指参数：thumb、index、middle、ring、pinky。
每指选择后读取 metadata，再按 descriptor 解码 little-endian 字段；之后在同一连接缓存 metadata。
一般文本为 UTF-8，descriptor 语法为 ASCII：`语义_类型_数量`，各段用分号连接。

| 样本字段 | 解释 |
| --- | --- |
| `sensor.metadata.selected_sensor / sensor_name` | 协议选择号 1..5 与稳定指名 |
| `sensor_type / data_unit / data_range` | 设备上报的类型、单位、量程原值；不自行补物理比例 |
| `maximum_rows / maximum_columns` | 传感器声明的最大尺寸 |
| `requested_rows / requested_columns` | 设备返回的请求窗口配置；不是返回点数保证 |
| `valid_data_position_mode / rectangle_fill` | 设备返回的模式/填充标记；不触发 SDK 自动 reshape |
| `descriptor_text / field_descriptors / total_data_length` | 字段语义、类型、数量、字节偏移与总长度 |
| `available` | metadata 是否描述可读数据；缺失不同于零力 |
| `sensor.raw_data` | 完整传感器数据 bytes，按 descriptor 字节顺序保存 |
| `sensor.fields` | 各段的原始数值，保留 semantic、类型、数量和偏移 |

`Fn/Ft/Fd` 表示法向/切向/切向方向，`FnS/FtS/FdS` 是对应合力/方向，`Px` 为接近量，
`x/y/z/xyz` 表示单轴或三轴交错字段。`Rsv` 表示保留字段，不是力；其长度影响后续偏移。
不能为方向、坐标、保留字段套用法向力单位，也不能把传感器总单位视为所有字段均已完成标定。

本机示例 descriptor 为 `FnS_U16_1;Fn_U8_70`：前两字节为一个小端合力值，之后为 70 个
u8 法向值，共 72 字节；metadata 报告 10×7、单位 `g`。SDK 不将其换算成 N、不由 70 点求和
替代设备 FnS。当前采集未确认人为受压，因此“回包正确”不代表力传感器已完成物理校准。

```python
from linkerbot_hand import NormalForceResultantSample

force = hand.get_force(timeout=1.0)
for sensor in force.sensors:
    print(sensor.metadata.sensor_name, sensor.metadata.available)
    print(sensor.metadata.data_unit, sensor.raw_data)
    for field in sensor.fields:
        print(field.semantic, field.values)

# 复用同一次采样；五指必须都有一个标量 FnS。
resultant = NormalForceResultantSample.from_force_sample(force)
print(resultant.sensor_names, resultant.raw, resultant.units)
# hand.get_normal_force_resultant(timeout=1.0) 则主动进行一次新的 force 读取。
```

合力接口要求五指都有单个标量 FnS，否则抛 `UnsupportedOperationError`，不填零。
force 的旧 `raw`/`tactile` 在 O30 为空；统一字段读取 `fn/fns/...`，完整流仍在
`sensors`。其他六型号保留矩阵 `tactile`，并提供统一 `fn` 字段。
触觉组包按 EDL 排除 CAN FD padding，metadata 有效 descriptor 最长 64 字节，可分片完成；
不能把单帧 61 字节载荷上限当作 descriptor 总长度上限。

## 时序、版本与验证边界

能力声明的 30 Hz 角度、10 Hz 触觉是单通道建议，不是联合吞吐上限。触觉每阶段估时
3 ms、响应超时 100 ms、整次声明估时 200 ms 是不同概念；冷启动还需读取 metadata。
原实机组合测试达到 100 Hz 角度写 + 100 Hz 主动查 + 20 Hz 触觉；请求 30 Hz 触觉时约
21.2 Hz 且有 missed deadlines，不能对外保证 30 Hz。该数据只描述特定主机、链路和设备。

支持记录：当前固件 1.1.0/HOP 0.0.4 已确认身份、表中读取、可逆配置读写和五指触觉通信。
加速度、电压、转矩等对象不能因文档删除线而认定设备不支持；寄存器可写/回读也不等于
物理控制效果已验证。未知或不可用功能按实际响应报错，不用固件版本作为连接限制。

尚需分别确认：有效关节到机械轴映射、触觉受压响应、SI 0x71/0x72 模式及请求窗口对实际
数据的作用、0x43 物理单位/比例、增量与稀疏位置的不同返回语义。当前实机身份采用与表格
一致的 249 字节布局，SDK 同时保留设备原始身份供核查。

协议定义但当前未提供稳定公共接口的功能包括：36 槽动态映射/有效关节、半字位置、PID、
增量位置、稀疏位置、传感器窗口设置、预设动作、0x43 单位主动查询、调试/统计/通信错误
历史、ID 修改与维护操作。各项应单独验证和设计，不把本轮缺陷修复等同于全协议已开放。
