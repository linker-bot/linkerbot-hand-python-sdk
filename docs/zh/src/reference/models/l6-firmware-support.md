## 运行时行为

对固件可选查询（包括新增 `03/06/07/08`），若当前连接代尚未成功读取过，连续 3 次发生以下任一情况时，SDK 将它解释为该固件不支持该功能。期间成功读取会确认本连接代支持该通道，后续超时按运行错误报告，不重新判为不支持：

- 已发送查询但超时或返回空数据；
- 同 opcode 回复长度或结构不符合协议。

SDK 随后：

1. 前两次 getter 返回原始 `TimeoutError` 或 `ProtocolError`，第三次返回 `UnsupportedFirmwareError`；
2. 在 `firmware_unsupported_telemetry` 标记该单一通道；
3. 停止该通道的后续轮询和显式发送；
4. 记录瞬时失败和最终降级 warning，但保持连接和其他命令/查询运行；
5. 下一次重新连接或恢复时清除该运行时判断并重新探测。

transport 发送失败不属于“固件不支持”，仍按连接故障处理。写命令也不会因超时被静默降级：它会让对应 `CommandHandle` 进入 `FAILED`，避免应用误以为配置已生效。

后续实机验证新增证据时，应记录固件、硬件/机械版本、传感器变体、CAN 配置、请求帧、响应帧、超时阈值和测试日期；不能只根据版本号推测支持关系。
