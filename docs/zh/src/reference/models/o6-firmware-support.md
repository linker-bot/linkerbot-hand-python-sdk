# O6 固件功能证据

SDK 实现最新 O6 协议，不按版本号拒绝旧手连接。本表记录资料和实机证据，不作为硬编码
版本门槛。

| 固件 / 来源 | 已确认支持 | 已知不支持或未确认 | 结论 |
| --- | --- | --- | --- |
| V1.1.2+，协议 V1.0.1 声明范围 | 资料列出 O6 型号文档中的全部 opcode | 资料声明不等于每台设备实测；早期固件范围未描述 | 作为最新 SDK 协议定义来源，不作为连接门槛 |
| 2026-08-28 项目 O6 实机 | 等设备完成身份核对和安全回归后补录 | SocketCAN 接口只有 TX、尚未观察到设备 RX，不能据此判断单项协议不支持 | 保持待验证，不把整机无响应误报为固件缺少某个功能 |

## 运行时行为

身份已验证并完成基础连接后，对 capability 标为固件可选的 O6 查询，当前连接代第一次发生
以下任一情况时，SDK 将它解释为该固件不支持该功能：

- 已发送查询但超时或返回空数据；
- 同 opcode 回复长度或结构不符合协议。

当前可单功能降级的 O6 查询包括配置速度、配置加速度、温度、五指触觉以及
`C5/C6/C7` 三项堵转配置。SDK 随后：

1. 让本次 getter 返回 `UnsupportedFirmwareError`；
2. 在 `firmware_unsupported_telemetry` 标记该单一通道；
3. 停止该通道的后续轮询和显式发送；
4. 记录一次 warning，但保持连接和其他命令/查询运行；
5. 下一次重新连接或恢复时清除该运行时判断并重新探测。

角度、故障和电流限制是当前连接 baseline；它们失败表示尚未建立可安全使用的完整连接，
不会伪装成某个已连接设备的单功能缺失。transport 发送失败同样属于连接故障。写命令不会
因超时被静默降级：对应 `CommandHandle` 会进入 `FAILED`，避免应用误以为配置已生效。

后续实机验证新增证据时，应记录固件、硬件/机械版本、传感器变体、CAN 配置、请求帧、
响应帧、超时阈值和测试日期。角度与触觉频率还应区分请求 Hz、完整事务 Hz、完成率、超时、
丢帧、总线负载和测试时长，不能只记录应用循环或 ROS publish Hz。
