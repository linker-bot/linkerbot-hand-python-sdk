# O6 固件功能证据

SDK 实现最新 O6 协议，不按版本号拒绝旧手连接。本表记录资料和实机证据，不作为硬编码
版本门槛。

出厂编码与传感器变体同样不作为能力门槛。`04-B` 只是目前唯一有实机证据的组合，`02-B`、
`03-B`、`05-B` 等同样可能带触觉硬件，而出厂编码本身并不描述点阵布局。因此触觉通道对所有
O6 开放，实际可用性由下面的运行时降级判定。

| 固件 / 来源 | 已确认支持 | 已知不支持或未确认 | 结论 |
| --- | --- | --- | --- |
| V1.1.2+，协议 V1.0.1 声明范围 | 资料列出 O6 型号文档中的全部 opcode | 资料声明不等于每台设备实测；早期固件范围未描述 | 作为最新 SDK 协议定义来源，不作为连接门槛 |
| V3.0.4，2026-08-29 至 2026-08-30 项目实机 | `0x01/0x02/0x05/0x33/0x35/0x87`、`C0/C1/C2/C4`、`C5/C6/C7` 与 `B1..B5 A4` 均有结构正确响应；身份为 `LHO6-04-453-R-B-1-D`，确认 10x4 五指触觉 | 未提供实测速度与清错操作；历史响应记录不能确定电流的物理比例 | 最新查询集合、可恢复配置写入和完整触觉可用 |

2026-09-21 语义更正：根据用户确认，`0x02` 主动读取返回当前电流，SDK 改用
`get_currents()`；写回复返回发送的限制值，`get_current_limits()` 只读取该写回复缓存。
此前“不支持实测电流”和“主动查询限制”的表述有误。此更正通过模拟协议与运行时
测试验证，未新增实机验证或固件覆盖证据；
资料的两种 mA 比例仍保留为冲突，不宣称完成物理标定。

## 运行时行为

身份已验证并完成基础连接后，对 capability 标为固件可选的 O6 查询，当前连接代连续 3 次
发生以下任一情况时，SDK 将它解释为该固件不支持该功能；期间任一次成功读取会清零计数：

- 已发送查询但超时或返回空数据；
- 同 opcode 回复长度或结构不符合协议。

当前可单功能降级的 O6 查询包括配置速度、配置加速度、温度、五指触觉以及
`C5/C6/C7` 三项堵转配置。SDK 随后：

1. 前两次 getter 返回原始 `TimeoutError` 或 `ProtocolError`，第三次返回 `UnsupportedFirmwareError`；
2. 在 `firmware_unsupported_telemetry` 标记该单一通道；
3. 停止该通道的后续轮询和显式发送；
4. 记录瞬时失败和最终降级 warning，但保持连接和其他命令/查询运行；
5. 下一次重新连接或恢复时清除该运行时判断并重新探测。

角度、故障和当前电流是当前连接 baseline；它们失败表示尚未建立可安全使用的完整连接，
不会伪装成某个已连接设备的单功能缺失。transport 发送失败同样属于连接故障。写命令不会
因超时被静默降级：对应 `CommandHandle` 会进入 `FAILED`，避免应用误以为配置已生效。

后续实机验证新增证据时，应记录固件、硬件/机械版本、传感器变体、CAN 配置、请求帧、
响应帧、超时阈值和测试日期。角度与触觉频率还应区分请求 Hz、完整事务 Hz、完成率、超时、
丢帧、总线负载和测试时长，不能只记录应用循环或 ROS publish Hz。
