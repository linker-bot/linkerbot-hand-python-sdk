# L20 接口、原始单位与实机边界

统一触觉字段为 `fn`：`get_force("fn", timeout=1.0)` 返回五指原始矩阵测点，
`force_fn_hz` 或默认简写 `force_hz` 控制同一查询；不支持 fns/ft/fts/fd/fds/px。
不将 L20Lite 标量协议类推到本型号；字段契约见[全型号触觉接口](../force.md)。

本文描述当前 SDK 的 L20 classic CAN 路径。协议资料与实机结论分开记录；固件证据见
[L20/L20Lite 固件支持记录](./l20-family-firmware-support.md)。SDK 不按版本号拒绝旧手。

## 连接与公共向量

- 构造使用 `model="L20"`，`side="left"` 或 `"right"`；经典 CAN、标准帧、1 Mbit/s。
  接口须由调用方配置并启用，声明的速率不等于 SDK 已修改系统网卡配置。
- 默认左手 ID `0x28`，右手 `0x27`。当前公共接口不设置设备地址。
- `LHT20-010-499-L-B-1-D` 等出厂编号按原值保留。身份验证同时核对工厂型号、侧别和版本；
  历史工厂前缀只用于设备识别，不作为公共构造型号别名。
- 公共向量是 16 个有效关节，不是五帧中的全部 30 个槽。写入保留槽填零，读取时丢弃。

每指线上槽顺序为 `yaw, roll, root1, root2, root3, tip`：

| 手指 / 角度 opcode | 公共 index 与名称 | 保留槽 |
| --- | --- | --- |
| thumb / `41` | 0 thumb_rotation，1 thumb_roll，2 thumb_root，3 thumb_tip | root2、root3 |
| index / `42` | 4 index_abd，5 index_root，6 index_tip | roll、root2、root3 |
| middle / `43` | 7 middle_abd，8 middle_root，9 middle_tip | roll、root2、root3 |
| ring / `44` | 10 ring_abd，11 ring_root，12 ring_tip | roll、root2、root3 |
| pinky / `45` | 13 pinky_abd，14 pinky_root，15 pinky_tip | roll、root2、root3 |

全部向量值均为 `u8` 原值 `0..255`。数值接口不查 LUT、不隐式换算为角度、速度或力。
角度投影中的百分比是固定端点映射；`physical_rad` 没有已确认映射的轴为 `None`。
本次实机验证确认帧槽到公共向量的数字映射，没有完成逐轴物理角度标定。

## 当前开放接口

表中查询都需要传 `timeout`；`get_snapshot()` 和 `get_capabilities()` 只读内存。

| 接口 | 请求与回复 | 单位、语义及成功含义 |
| --- | --- | --- |
| `set_angles(values)` | `41..45`，每指 6 个槽；返回当前角度 | count；写回复发布为 `DEVICE_COMMAND_FEEDBACK`；`returns_current_state=True`；终态 `DISPATCHED` 不表示机械到位 |
| `set_percent_angles(values)` | 16 个 `0..100` 经固定映射生成上述原值 | `raw=0` 对应 0%，`raw=255` 对应 100%；各轴方向查 `percent_mapping`，侧摆/旋转轴的 100% 不等于屈伸轴的“张开” |
| `set_speeds(values)` | `49..4D`，每指 6 个槽 | count；目标速度的逐轴物理比例未确认；终态 `DISPATCHED`，SDK 不校验写回包，也不生成配置读取值 |
| `set_current_limits(values)` | `51..55`，每指 6 个槽 | 电流限制原始 count，比例未知；终态 `DISPATCHED` |
| `get_angles(timeout)` | 单字节 `41..45`，组装五片 | 16 个 count；`DEVICE_RESPONSE` |
| `get_speeds(timeout)` | 单字节 `49..4D`，组装五片 | 16 个实时速度原值；count，比例未知；不是设定速度回读 |
| `get_currents(timeout)` | 单字节 `51..55`，组装五片 | 16 个实时电流原始 count；`DEVICE_RESPONSE`，不是限制设定值回读，不自动换算成 mA |
| `get_temperatures(timeout)` | 单字节 `61..65`，组装五片 | 16 个 `degree_celsius`；协议为 1 ℃/count，原数字已经是摄氏度 |
| `get_faults(timeout)` | 单字节 `59..5D`，组装五片 | 16 个 `u8_bitmask`；无物理单位，不使用 L20Lite 的位定义 |
| `get_force(timeout=...)` | `B1 C6` 至 `B5 C6` | 五指各 12×6 `u8` 矩阵；count，无可用 N/压力标定 |
| `get_device_info(timeout)` | `C0/C1/C2/C4` | 产品号、PCB/固件/机械版本、工厂侧别与传感器标识；版本三个字节分别为 major/minor/patch |
| `clear_faults()` | `59..5D` 各附六个 `01` | 当前实现仅报告 `DISPATCHED`，不等于故障已清除；须另查故障。资料文字与示例对清除值有冲突，尚未实测故障置位后的清除行为 |

`get_configured_speeds()`、`set_percent_speeds()`、`get_current_limits()`、转矩读写、加速度、堵转配置、
限位补偿、使能/失能/标定、保存参数均未声明支持，调用会报告 `UnsupportedOperationError`。
不能用 `get_speeds()` 或 `get_currents()` 的实时值恢复原先的配置。
电流查询使用 `PollingPlan(current_hz=...)`，样本在 `snapshot.currents`。

元数据查询示例（不产生 CAN 请求）：

```python
from linkerbot_hand import TelemetrySemantic

channel = hand.get_capabilities().telemetry_channel(TelemetrySemantic.FORCE)
print(channel.raw_unit)         # count
print(channel.raw_scale_note)   # 物理标定未知
print(channel.unit_confidence)  # UNKNOWN
```

## 触觉与轮询

`get_force()` 的 `raw` 是空元组；数据在 `sample.tactile`，顺序为 thumb、index、middle、
ring、pinky，每项的 `raw` 是 12 行、每行 6 点。`sample.sensors` 为空，没有 descriptor
或合力接口。不能把 72 点相加称作牛顿合力，也不能从全零矩阵判断没有传感器。

SDK 按行标记组装矩阵，接受直编号和高半字节行号。每指收齐再请求下一指，边界可调度
有界数量的完整多帧角度读写；五指收齐才原子发布。这不保证五指同时物理采样。
缺行或冲突不发布部分矩阵。实机 1.0.18 在每指 12 行后还返回 `Bx FF 00 00`；该尾帧
不计入矩阵，后续手指和角度事务不消费其他手指的尾帧。尾帧数据的物理含义未确认。

声明的单通道推荐值为角度 60 Hz、实时速度/电流/触觉 30 Hz、温度 1 Hz、故障 5 Hz；
组合开启后的容量必须另外验证。向量事务估时 8 ms，五指触觉整次估时 20 ms；
向量响应超时 100 ms、触觉每指响应超时 150 ms，超时不是采样周期或性能承诺。
实测短时 100 Hz 写入并复用反馈、30 Hz 触觉可达请求速率；独立角度查询叠加写入仍观察到
一次超时，不能作为所有策略、固件和持续时间的稳定上限。

可选降级覆盖实时速度、温度、触觉。当前连接从未读成功的通道连续三次超时/结构错误后，
返回 `UnsupportedFirmwareError` 并停止该通道请求；已成功通道的偶发丢帧仍按通信异常报告，
不误报固件不支持。重连重新判定。身份与角度、故障、电流仍是连接所需基线。

## 故障位与单位证据

| bit / mask | 协议含义 |
| --- | --- |
| 7 / `80` | 电机通信异常 |
| 6 / `40` | soft_rotor_lock：抓握时可能置位，松开后自恢复，无需手动清除 |
| 5 / `20` | 过温 |
| 4 / `10` | 电机自检异常 |
| 3 / `08` | 电机电压异常 |
| 2 / `04` | 电机失速 |
| 1 / `02` | 电机过流 |
| 0 / `01` | 电机堵转 |

温度与故障说明来自协议（`DOCUMENTED`），本次未主动制造故障。触觉、速度和电流的
物理比例为 `UNKNOWN`。资料中的速度端点混用 rpm、mm/s，部分轴为空；负载表虽有 mA
端点，但没有证明实时查询与配置使用同一个物理映射，因此 SDK 不做跨轴统一换算。

## 尚未开放与验证的对象

- `B0` 传感器类型：本次只读实测返回 `02`，资料含义为矩阵；尚无独立公共 getter，
  `sensor_variant` 是产品号字段，不能冒充 B0 的查询结果。
- `C3` 地址读取/修改：只读实测返回 `28`；修改在重启后生效，当前未开放管理接口。
- 并联与五指综合控制是其他帧组织形式，当前 SDK 使用每指串联帧覆盖有效关节。
- `90..93`、`98..9C`、`B6` 是资料中的预留项；没有依据将其作为已实现能力。
- `CD` 擦除校准未执行、未开放；速度/电流写入未做实机修改，因为查询值不能恢复原配置。

单台左手验证不等于右手、其他固件、触觉受压标定和全部机械行程已经验证。
